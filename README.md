# TokenGuard (hosted SaaS)

**v0.1.0** — 1-click hosted OpenAI-compatible proxy with loop-stop middleware and a token-waste impact dashboard.

Sign up → get personal `base_url` (`https://HOST/v1`) + API key (`tg_…`) → point Claude Code / Continue / any OpenAI client.

> Savings = **estimate** unless the provider returns `usage`.  
> **Demo mode** = simulated FakeAgent sessions (~75% est.) — labeled simulated.  
> Billing MVP: `BILLING_MODE=free` (open signup, no Stripe).

## Local run (uvicorn)

```bash
cd /workspace/grok-dev/tokenguard-saas
./run.sh
# → http://127.0.0.1:8080/
```

Or:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export DATA_DIR=./data HOST=0.0.0.0 PORT=8080
export PUBLIC_BASE_URL=http://127.0.0.1:8080
export TOKENGUARD_SECRET=local-dev-secret   # auto-generated if omitted (non-prod)
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

## Local run (Docker)

```bash
docker compose up --build
# → http://127.0.0.1:8080/health
```

SQLite persists on volume `tokenguard_data` → `/data`.

## One-click user path

1. Open public URL → **Sign up** (email + password)
2. Land on **Dashboard** with `base_url` + `tg_…` key
3. Optional: paste upstream xAI/OpenAI key on **Integrations** (Fernet-encrypted with `TOKENGUARD_SECRET`)
4. Point client: `base_url` + `Authorization: Bearer tg_…`
5. Or click **Demo mode** (no provider key) — simulated ~75% est.

## Env vars (deploy)

| Var | Required | Purpose |
| --- | --- | --- |
| `TOKENGUARD_SECRET` | **yes in prod** | Fernet key material for encrypting BYOK upstream keys |
| `PUBLIC_BASE_URL` | recommended | e.g. `https://tokenguard.example.com` — used in UI snippets |
| `DATA_DIR` | `/data` in Docker | SQLite + secret file path |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | Bind address |
| `BILLING_MODE` | `free` | MVP stub (no Stripe) |
| `XAI_API_KEY` / `GROK_API_KEY` | optional | Shared server-side upstream fallback |
| `DEFAULT_UPSTREAM` | `https://api.x.ai/v1` | Default provider base |
| `DEFAULT_MODEL` | `grok-4.7` | Default model id |
| `ENV` / `ENVIRONMENT` | `production` | Requires `TOKENGUARD_SECRET` (no auto-gen) |

## Deploy

### Railway (recommended next human step)

1. Push this folder to a GitHub repo (or `railway up` from CLI).
2. New Project → Deploy from Dockerfile (`railway.json` present).
3. Add volume mounted at `/data`.
4. Set secrets: `TOKENGUARD_SECRET`, `PUBLIC_BASE_URL=https://YOUR.up.railway.app`.
5. Optional: `XAI_API_KEY`.
6. Open the public URL → Sign up.

```bash
# CLI sketch
railway login          # ← human sign-in needed
railway init
railway up
railway variables set TOKENGUARD_SECRET=$(openssl rand -hex 32)
railway variables set PUBLIC_BASE_URL=https://YOUR.up.railway.app
railway volume add /data
```

### Render

1. New → Blueprint → `render.yaml` (or Web Service + Dockerfile).
2. Disk `/data` (1 GB).
3. Set `PUBLIC_BASE_URL` to the `onrender.com` URL after first deploy.
4. `TOKENGUARD_SECRET` auto-generated by blueprint.

### Fly.io

```bash
fly auth login         # ← human sign-in needed
fly launch --no-deploy --copy-config
fly volumes create tokenguard_data --size 1
fly secrets set TOKENGUARD_SECRET=$(openssl rand -hex 32) PUBLIC_BASE_URL=https://YOURAPP.fly.dev
fly deploy
```
